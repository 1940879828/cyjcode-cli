# 软件开发细分计划 P1 — 基础版 MVP（v0.1）

> 来源：`软件开发总计划.md` → 第 4 章 P1 阶段
> 目标版本：v0.1
> 目标：跑通"配置 → 对话 → 工具调用 → 日志"最小闭环

---

## P1 总体目标

打通从终端输入到 LLM 回复、工具执行、日志落盘的全链路。用户执行 `npm run dev` 后可完成引导配置、多轮对话、通过对话让 agent 读写当前目录文件，并在另一个终端通过 `logs` 子命令实时查看彩色日志。

---

## 子阶段划分

P1 按依赖关系拆为 8 个子阶段，严格串行推进：

```
P1.1 骨架 → P1.2 LLM 客户端 ↘
                              P1.4 Agent 循环 → P1.6 SetupWizard
P1.1 骨架 → P1.3 工具系统 ↗                 → P1.5 聊天 UI ↗
                                      P1.7 日志系统 ─────────→ P1.8 串联集成
```

## P1.1 — 基础骨架搭建

**优先级**：P0（阻塞所有后续模块）

### 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|---------|------|
| 1.1.1 | 创建 `src/` 目录结构 | 全部子目录 | 按总计划 3.1 节的模块划分建好目录骨架 |
| 1.1.2 | 实现 `src/cli.tsx` 入口 | `src/cli.tsx` | yargs 解析子命令：无子命令 → App；`logs` → LogViewer；内置 `--version` / `--help` |

## P1.2 — LLM 流式客户端

**依赖**：P1.1（配置模块、Ink 骨架）
**优先级**：P0

### 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|---------|------|
| 1.2.1 | 定义 LLM 相关类型 | `src/llm/types.ts` | `ChatMessage`、`ToolCall`、`StreamEvent`（text_delta / tool_call_delta / done / error）等核心类型 |
| 1.2.2 | 实现流式调用 | `src/llm/client.ts` | 基于 `openai` SDK 的 `chat.completions.create({stream:true})`，从 config 读取 baseUrl/apiKey/model |
| 1.2.3 | 实现 text delta 解析 | `src/llm/client.ts`（同文件内） | 遍历 SSE chunk，提取 `choices[0].delta.content` |
| 1.2.4 | 实现 tool_calls 累积 | `src/llm/client.ts`（同文件内） | 跨 chunk 累积 `delta.tool_calls[]`，按 index 聚合 function name + arguments JSON 片段 |
| 1.2.5 | 编写冒烟测试脚本 | `src/llm/client.ts` 或临时 test 函数 | 硬编码一条消息，调 `streamChat()` 看 text delta 和可能的 tool_calls |

### 验收标准

- 连接真实 API 端点发起一次流式 chat 请求
- text delta 能逐 chunk 输出到控制台
- 若模型返回 tool_calls，能完整还原 function name + arguments JSON

## P1.3 — 工具系统

**依赖**：P1.1（目录骨架、配置模块，但不阻塞 LLM 与 UI 开发）
**优先级**：P1

### 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|---------|------|
| 1.3.1 | 定义 `Tool` 接口 | `src/tools/types.ts` | `name` / `description` / `parameters`（zod schema）/ `execute(args)` / 工具返回格式 |
| 1.3.2 | 实现 `listDir` 工具 | `src/tools/listDir.ts` | 调用 `fs.readdir`，参数 `path`（默认 `.`）、`recursive`（默认 false） |
| 1.3.3 | 实现 `search` 工具 | `src/tools/search.ts` | 调用 `child_process.exec('rg ...')` 或 Node fs 递归搜索，参数 `pattern`、`path`、`fileTypes` |
| 1.3.4 | 实现 `read` 工具 | `src/tools/read.ts` | 调用 `fs.readFile`，参数 `filePath`、`offset`、`limit` |
| 1.3.5 | 实现 `write` 工具 | `src/tools/write.ts` | 调用 `fs.writeFile`（仅允许在工作目录下），参数 `filePath`、`content` |
| 1.3.6 | 实现 `rename` 工具 | `src/tools/rename.ts` | 调用 `fs.rename`，参数 `oldPath`、`newPath` |
| 1.3.7 | 实现工具注册表 | `src/tools/index.ts` | `allTools: Tool[]` + `getTool(name)` + `toolsToOpenAI()` 转 JSON Schema 列表 |

### 验收标准

- 每个工具可独立 import 并调用 `execute()`，返回结构化结果
- `toolsToOpenAI()` 产出的 JSON Schema 可被 LLM 理解
- 所有工具对非法参数（路径穿越等）有防御并返回错误

## P1.4 — Agent 主循环

**依赖**：P1.2（LLM 客户端） + P1.3（工具注册表）
**优先级**：P0

### 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|---------|------|
| 1.4.1 | 定义 Agent 事件类型 | `src/agent/types.ts` | `AgentEvent`：`user_message` / `text_delta` / `tool_call` / `tool_result` / `turn_start` / `turn_end` / `done` / `error` |
| 1.4.2 | 实现消息历史管理 | `src/agent/history.ts` | 内存 `ChatMessage[]`，`addMessage()` / `getMessages()` / `appendToolResult()` |
| 1.4.3 | 实现 `runAgentLoop` | `src/agent/loop.ts` | `AsyncGenerator<AgentEvent>`：① yield user_message → ② 调 LLM 流式，逐 chunk yield text_delta → ③ 若 LLM 返回 tool_calls，逐个执行工具并 yield tool_call + tool_result，将 tool result 追加到历史 → ④ 回到 ② 继续循环（最多 10 轮） → ⑤ 无 tool_calls 时 yield done |
| 1.4.4 | 实现 system prompt 构建 | `src/agent/prompt.ts` | 注入可用工具列表、当前工作目录、基础行为约束 |

### 验收标准

- 在测试脚本中手动构造一条用户消息传入 `runAgentLoop`，逐事件打印到控制台
- 能完成至少一轮"用户提问 → LLM 回复（含 text + tool_calls）→ 工具执行 → 工具结果返回 LLM → LLM 最终回复"的完整多轮对话
- 连续工具调用 10 轮后自动终止，不会死循环

## P1.5 — Ink 聊天 UI

**依赖**：P1.1（Ink App 骨架）
**优先级**：P0

### 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|---------|------|
| 1.5.1 | 实现 `useChat` hook | `src/ui/useChat.ts` | 封装 `runAgentLoop` 调用，管理界面状态：`messages: ChatMessage[]` / `isStreaming: boolean` / `sendMessage(text)` |
| 1.5.2 | 实现消息列表组件 | `src/ui/MessageList.tsx` | Ink `Box` + `Text` 渲染对话历史，区分 user / assistant / system / tool 消息角色，用 chalk 着色 |
| 1.5.3 | 实现输入框组件 | `src/ui/InputBox.tsx` | Ink `useInput` 捕获用户输入，Enter 提交，支持多行文本输入 |
| 1.5.4 | 实现流式输出渲染 | `src/ui/MessageList.tsx` 或 `src/ui/StreamingText.tsx` | 助手消息在 `isStreaming` 状态下实时追加 text delta |
| 1.5.5 | 实现斜杠命令框架 | `src/ui/commands.ts` | 命令注册表 `Command[]`，输入以 `/` 开头时匹配并执行 handler；内置 `/help`（列出所有命令）、`/config`（显示当前配置） |
| 1.5.6 | 将 useChat 接入 App | `src/ui/App.tsx` | 整合 MessageList + InputBox + 状态机：若未配置 → SetupWizard（占位），否则 → 聊天界面 |

### 验收标准

- 终端启动后显示输入框，输入文本按 Enter 发送
- 助手回复逐字流式出现在消息列表中
- 输入 `/help` 显示所有命令列表，`/config` 显示当前配置

## P1.7 — 日志系统 + LogViewer

**依赖**：P1.1（utils 目录），但与上述阶段可**并行开发**
**优先级**：P1

### 任务清单

| # | 任务 | 产出文件 | 说明 |
|---|------|---------|------|
| 1.7.1 | 实现 JSONL Logger | `src/utils/logger.ts` | 统一接口如 `log(eventType, data)`，自动按天分割文件到 `~/.cyjcode/logs/YYYY-MM-DD.jsonl`，自动 `mkdir -p`；事件类型：`session.start` / `llm.request` / `llm.response` / `tool.start` / `tool.end` / `error` |
| 1.7.2 | 实现 LogViewer 核心 | `src/ui/LogViewer.tsx` | Ink 组件：用 `setInterval` 轮询 tail 当日日志文件（每 500ms），增量解析新行，渲染格式化日志列表；使用 chalk 按事件类型着色 |
| 1.7.3 | 接入日志子命令 | `src/cli.tsx` | `logs` 子命令进入 LogViewer 模式（一个纯 Ink 渲染的独立界面） |
| 1.7.4 | 在关键节点埋点 | 各模块内 | 在 `runAgentLoop`、LLM client、工具 execute 中调用 `log()` |

### 验收标准

- 对话过程中 `~/.cyjcode/logs/` 下有当日 `.jsonl` 文件，内容可读
- `tsx src/cli.tsx logs` 启动 LogViewer，实时滚动显示新日志
- 不同事件类型用不同颜色区分（如 llm.request 蓝色、tool.end 绿色、error 红色）

## 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Ink 流式渲染组件性能问题 | P1.5 延期 | `useInput` + `useEffect` 逐帧更新，若卡顿则降级为"完整块输出"而非逐字 |
| OpenAI SDK v6 API 变动 | P1.2 受阻 | 锁定 `openai@^6.44.0`，按当前文档编码 |
| Windows 下 fs.watch 不可靠 | P1.7 LogViewer 不稳定 | 已采用轮询方案（每 500ms tail），避开此问题 |
| 工具执行错误未妥善处理 | P1.4 流程中断 | 每个工具 try/catch 后返回结构化错误，不抛异常到 agent 循环 |
| agent 陷入工具调用死循环 | P1.4 无限循环 | MAX_ROUNDS = 10 硬限制，超出后 yield error 事件并退出 |
